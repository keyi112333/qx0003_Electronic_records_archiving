## 1. 业务范围与系统边界

### 1.1 业务目标

1. 根据指定路径获取待处理单据；根据获取的待处理单据文件名中包含的报关单号和合同号分组；获取报关相关六类文件、一卡通扫描件、BIP销售发票。
2. 按报关单号在OA创建或复用唯一主记录；仅对已确认由机器人新增的单据上传必要附件、补齐及维护源附件关联。
3. 对机器人新增单据比对源附件ID和更新时间，同步新增、更新和删除。历史或人工新增单据不进入此维护分支。
4. 用户手工确认完整后，机器人读取OA现有附件（所有状态为确认已完成归集），下载附件按组织配置顺序整理PDF，更新OA（更新成已归集为PDF）、更新结果表；此范围包括历史单据。
5. PDF打印暂不实施；本流程保留归集PDF及查看链接。
6. 按组织、出口日期所属年度更新结果表，通过邮件及企微反馈运行结果。

### 1.2 范围内

| 序号 | 内容 | 说明 |
|------|------|------|
| 1 | OA 无流程表单主记录创建与复用 | 报关单号为唯一值，合同编号用于关联附件 |
| 2 | OA 各明细区附件上传、补齐、删除 | 仅机器人创建的单据 |
| 3 | 一卡通、BIP、QX0002 共享目录附件获取 | 单一窗口仅作人工兜底 |
| 4 | 附件快照比对与增删同步 | 按附件ID+更新时间 |
| 5 | 归集 PDF 生成、落盘、更新 OA、状态回写 | 含历史单据 |
| 6 | 运行结果表“明细”页签维护新增数据，打印页维护所有确认已完成归集单据 | 按组织、出口日期所属年度 |
| 7 | 邮件与企微运行结果反馈 | 跨年度时发送多份结果表 |
| 8 | 日志、异常截图、审计记录 | 共享盘留存 |

### 1.3 范围外

| 序号 | 内容 | 说明 |
|------|------|------|
| 1 | 用户人工确认附件完整性 | OA 人工节点，机器人不代替 |
| 2 | OA 状态“待用户确认”“确认已完成归集”的流转 | 由 OA 自动/人工维护 |
| 3 | 电子口岸/单一窗口的批量下载 | 由 QX0002 流程负责并落共享盘 |
| 4 | 打印归集单证 | 本期不实施，仅预留设计（见第 10 章） |
| 5 | 多机器人并行 | 固定 1 个机器人、单实例运行 |
| 6 | 数据库存储 | 结果表、日志、截图均落共享文件夹 |

### 1.4 关键业务约束

1. 报关单号在 OA 为唯一值；同一报关单号+合同编号重复命中时禁止自动新建，转人工确认。
2. 机器人只维护创建人为 RPA 的单据的源附件；历史/人工单据只做 PDF 归集。
3. 机器人不修改“待用户确认”“确认已完成归集”；只把单据推进到“已归集为PDF”。
4. “归集PDF时间”必须与 OA 侧时间一致，误差不超过 2 秒。
5. 结果表按“组织 + 出口日期所属年度”分文件存放；跨年度需分别更新、分别发送。
6. 结果表所在共享文件被用户打开时会导致保存失败，程序需给出明确提示并重试。

## 2. 术语与数据约定

| 术语 | 定义 |
|------|------|
| 组织/公司 | 组织即公司。OA 按组织上传附件类型；珠海、泰兴、荆门为已知组织 |
| 触发点1 | 机器人获取到新的报关单/放行通知单/电子委托协议/发票/装箱单/报税核注清单时，在 OA 新增主记录并上传附件 |
| 触发点2 | 必要附件检查与补齐、源附件变更同步 |
| 触发点3 | 用户置“确认已完成归集”后，生成归集 PDF 并回写 |
| 必要附件 | 由 OA 配置表（接口导出）按组织维护的“xx是否必要”字段确定 |
| 归集 | 按配置顺序把多类附件合并为一个 PDF |
| 附件ID号 | 一卡通附件 `id`、BIP 发票附件ID；共享盘文件使用稳定内容标识（见 7.4） |
| 源更新时间 | 一卡通 `time`、BIP `BIP附件更新时间`，精确到秒 |
| 机器人归属 | OA 明细行“归集人=RPA”，用于区分人工上传 |
| 基线时间 | 上一次成功运行的结束时间，用于筛选源侧变更 |

### 2.1 时间与格式约定

| 数据 | 格式 | 说明 |
|------|------|------|
| 日期 | `yyyy-mm-dd` | 出口日期 |
| 时间 | `yyyy-mm-dd HH:mm:ss` | 创建时间、归集时间、打印时间 |
| 运行ID | `yyyyMMdd_HHmmss` | 单次运行唯一标识 |
| 布尔展示 | `是`/`否` | 结果表附件存在标识 |
| 组织目录名 | 与 OA 组织全称一致 | 不做简写映射 |

## 5. 运行结果表设计

### 5.1 文件与路径

| 项 | 规则 |
|----|------|
| 文件名 | `{组织全称}-电子档案管理（单证归集与打印）-运行结果表-{YYYY}.xlsm` |
| 存放路径 | `{日志目录}/{组织全称}/{YYYY}/` |
| 年份取值 | 出口日期所属年度，缺失时取报关单日期，再缺失记异常 |
| 模板来源 | `docs/{组织全称}-电子档案管理（单证归集与打印）-电子档案管理（单证归集与打印）-运行结果表-YYYY.xlsm`，读取结果表样式（标题页签要一模一样），要程序生成使用（存在做追加） |
| 文件格式 | 保留 `.xlsm` 扩展名；当前模板无 VBA 工程，读写使用 `keep_vba=True` 兼容后续宏 |
| 并发控制 | 单实例锁 + 保存前重试；被占用时不覆盖，记录异常 |

> PDD 中“按 U 盾存放”与“按组织存放”为同一维度，程序统一使用组织全称作为一级目录。

**列扩展规则**：模板仅覆盖报关单、放行单、合同、提单、一卡通其他、销售发票、BIP其他七组。电子委托协议、发票、装箱单、保税核注清单、代理报关发票、国内运输发票、CIF保险单、国内运费形式发票按需扩展，每组固定三列（是否存在/路径/归集时间），统一插入到 AF 之后、AG“运行状态”之前，并同步更新表头常量与测试用例。

**表头定位规则**：

1. 以第 1 行表头文本为唯一依据，不使用硬编码列号。
2. 表头文本与模板完全一致（含错别字）优先匹配；常量中登记“合同归集时间”“合同归集时间时间”等别名。
3. 表头缺失/重复/合并单元格时终止写入，抛 `ImplementationRequired`，不猜测列。
4. 第 2 行为模板示例/说明行（G2 状态枚举、L2/O2/R2/U2 为“是”、打印页 H2/J2/K2 为示例公式）。程序默认从第 3 行开始写入；上线前需确认该行是删除还是保留为示例。

### 5.3 “打印”页签字段（A~K，共 11 列）

| 列 | 字段 | 格式 | 写入规则 |
|----|------|------|----------|
| A | 组织 | 文本 | 组织全称 |
| B | 报关单号 | 文本 | 唯一键 |
| C | 出口日期 | 日期 |  |
| D | 创建人 | 文本 | OA 创建人 |
| E | 创建时间 | 日期时间 | OA 创建时间 |
| F | 状态 | 文本 | 固定为 `已归集为PDF` 才入表 |
| G | 归集的PDF路径 | 超链接 | 与明细 H 列一致 |
| H | 归集PDF时间 | 日期时间 | 与明细 I 列一致 |
| I | 是否打印 | 文本 | 用户填“是”；打印后程序清空 |
| J | 打印时间 | 日期时间 | 打印成功后写入 |
| K | 打印后再次归集PDF？ | 公式 | `=IF((H{r}-J{r})>0,"是","否")` |

打印页第 2 行同样为模板示例（F2 状态、H2 `=NOW()`、J2 示例时间、K2 示例公式），数据从第 3 行开始写入。

### 5.4 写入算法

```text
upsert(workbook, sheet, key=(组织, 报关单号), row):
  1. 读取表头，建立 字段->列 索引，校验必需列
  2. 从数据起始行扫描，按 A+B 精确匹配
  3. 命中 0 行 -> 追加到 max_row+1
  4. 命中 1 行 -> 仅覆盖本程序负责的列，保留用户维护列（是否打印等）
  5. 命中多行 -> 抛 BusinessPending，不写入
  6. 时间列写 datetime 并设置 number_format='yyyy-mm-dd hh:mm:ss'
  7. 路径列设置 cell.hyperlink 与显示文本
```

保存要求：

1. 先写临时文件（同目录 `.tmp`），成功后 `os.replace` 原子替换。
2. 保存失败区分“文件被占用”（`PermissionError`）与其他错误；被占用时按配置间隔重试，最终失败记录到日志与通知。
3. 每张单据处理完立即落盘一次，避免整轮失败丢失结果。
4. 跨年度时按年份分组，分别打开对应工作簿写入。

### 5.5 跨年度处理

1. 先按 `export_date.year` 分组。
2. 每个年份一个结果表、一封邮件。
3. 企微通知正文列出各年份单据数与 PDF 数。
4. 结果表附件发送前复制到临时目录，避免源文件被占用。

### 7.2 一卡通

- 纯 HTTP 接口，无页面操作。
- 签名：`md5(key + ts + rand + json)`，32 位小写；先签名后 URL 编码。
- 查询：`no`=合同号，`time`=时间下限，返回 `data[{id,name,url,time,filetype,no}]`。
- 下载：直接使用返回 `url`，不传 `withfile`。
- 源ID：`id`；更新时间：`time`。
- 已知缺口：接口按时间下限过滤，不能据此判断“删除”；删除同步需全量快照或状态字段（见 18 章）。

## 8. 主流程设计

### 8.1 三模块流水线

主流程按“附件收集 → OA同步 → 合并PDF”三个模块串行编排。模块之间只通过数据对象传递，不直接操作对方系统。

| 模块 | 职责 | 输入 | 输出 | 访问系统 |
|------|------|------|------|----------|
| 模块一 附件收集 | 按单据汇总必要附件，从共享盘/一卡通/BIP/单一窗口获取并落盘 | `Declaration`、`OrganizationRules` | `CollectionPackage` | 共享盘、一卡通、BIP、单一窗口 |
| 模块二 OA同步 | 创建/复用主表，补齐与同步附件，读取状态 | `CollectionPackage`、OA 快照 | `OaSyncResult` | OA |
| 模块三 合并PDF | 按配置顺序合并 OA 现有附件，回写状态与结果 | `OaSyncResult`（状态=确认已完成归集） | `PdfResult` | OA、文件系统 |

触发点映射：触发点1（新单建表、上传附件）与触发点2（补齐、变更同步）由模块一、模块二共同完成；触发点3（归集 PDF）对应模块三。

设计原则：

1. 单向依赖：模块一只产出收集结果，不写 OA；模块二只消费收集结果，不重新下载；模块三只读 OA 附件，不重新收集。
2. 可独立重跑：三个模块均以单据键幂等，支持 `--stage collect|sync|pdf|all` 分段重跑。
3. 产物落盘：`CollectionPackage` 写入 `06_临时文件/{run_id}/collect/{组织}_{报关单号}/manifest.json`，重跑优先复用。
4. 失败隔离：单张单据、单个附件失败不阻断其他单据；每个模块分别记录结果与异常。

### 8.2 总时序

```
 初始化
 ->  读取入参、确定待处理单据
 ->  读取基线、OA历史、组织规则
 -> 对每张单据：
      模块一 附件收集   -> CollectionPackage
      模块二 OA同步     -> OaSyncResult
      模块三 合并PDF    -> PdfResult（仅满足触发条件时执行）
      结果表更新
 ->  汇总、通知、清理
```

#### 8.3.1 初始化

|----|------|

| 输出 | `run_id`、配置对象、上下文 |
| 失败 | 配置缺失/凭据不可用：终止并企微告警，不发送业务邮件 |
| 幂等 | 无 |

#### 8.3.2 确定待处理单据

| 项 | 内容 |
|----|------|
| 输入 | 入参（公司/报关单/期间）--允许为空、共享目录 |
| 处理 | 1) 指定报关单直接构造；2) 否则扫描 `{组织}/{YYYYMM}/{报关单号}-{合同编号}`；3) 从文件名解析报关单号与合同号；4) 按 `组织+报关单号` 分组；5) 同组多合同号时分别建单 |
| 输出 | `declarations` |
| 失败 | 报关单号/合同编号无法确定：该条记 `待人工`，继续处理其他单据 |

关键规则：

2. 出口日期取文件名中的日期；缺失时用报关单 PDF 文本解析。

#### 8.3.3 基线与组织规则

| 项 | 内容 |
|----|------|
| 输入 | `run_state.json`、OA 单张收集导出、OA 配置表 |

| 输出 | `last_run_time`、`history_by_key`、`rules` |
| 失败 | 配置表导出失败：终止（无法判定必要附件与顺序）；历史记录失败：可降级但记录告警 |
| 幂等 | 单轮缓存，只请求一次 |

规则选择顺序：公司名 → 组织编码；同一键多条且内容不一致时抛 `BusinessPending`，不任取第一条。

### 8.4 模块一：附件收集

**目标**：在进入 OA 前完成单张单据的附件定位与下载，输出“已收集/缺失/待人工”的明确结论。

**边界**：不读写 OA、不创建主表、不改变状态。

| 项 | 内容 |
|----|------|
| 输入 | `Declaration`、`OrganizationRules`、`路径配置.报关单证存放路径` |
| 输出 | `CollectionPackage`（附件清单、缺失清单、`complete`、manifest 路径） |
| 失败 | 单类失败记录后继续；全部失败时 `complete=False`，仍交模块二建主表 |

**步骤**：

1. **A1 生成需求清单**：取 `rules.required`，追加条件必要附件；规则为空或配置冲突时记 `待人工`，不猜测。
2. **A2 共享盘（QX0002）收集**：按 `{根路径}/{组织}/{YYYYMM}/{报关单号}-{合同编号}` 定位报关单、放行通知单、电子委托协议、发票、装箱单、保税核注清单；文件名匹配类型关键字，多候选记 `待人工`；不复制文件，登记源路径与 `sha256[:16]` 作为源ID。
3. **A3 一卡通收集**：按合同编号查询接口，下载合同、提单、代理报关发票、国内运输发票、CIF保险单、国内运费形式发票及其他扫描件；源ID取 `id`，更新时间取 `time`。
4. **A4 BIP 收集**：按报关单号查询销售发票；同一报关单多张发票取 `BIP附件更新时间` 最新的 PDF；国内运费形式发票按 BIP 实际模块获取；源ID取 `发票附件ID`。
5. 
6. **A6 完整性判定**：逐类标记 `已收集/缺失/多候选/格式异常`；仅当 `rules.required` 与条件必要附件全部已收集时 `complete=True`。--无需全部收集再上传记录缺少文件类型上传已收集文件
7. **A7 落盘**：附件保存到 `06_临时文件/{run_id}/collect/{组织}_{报关单号}/`，清单写 `manifest.json`（类型、来源、源ID、更新时间、路径、hash、缺失原因）。

**来源优先级**：

| 附件类型 | 首选 | 兜底 | 源ID |
|----------|------|------|------|
| 报关单、放行通知单、电子委托协议、发票、装箱单、保税核注清单 | QX0002 共享盘 | 无 | `sha256[:16]` |
| 合同、提单、代理报关发票、国内运输发票、CIF保险单、国内运费形式发票、一卡通其他 | 一卡通接口 | 共享盘同名文件（如配置） | 一卡通 `id` |
| 销售发票、BIP 其他附件 | BIP 销售发票附件/报表 | 一卡通同名文件（如配置） | BIP 附件ID |

**失败处理**：

| 场景 | 处理 |
|------|------|
| 共享盘不可读 | 记 `SystemFailure`，该单据收集失败，继续下一条 |--共享不可读则无新增报关单，只处理历史结果表且需要在通知时预警
| 一卡通接口失败 | 记 `一卡通待补`，保留其他来源结果 |
| BIP 查询失败 | 记 `BIP待补`，保留其他来源结果 |
| 同类多候选/文件名无法判定 | 记 `待人工`，不自动选择 |
| 必要附件缺失 | `complete=False`，模块二仍建主表并上传已有附件，模块三阻断 PDF |

### 8.5 模块二：OA同步

**目标**：保证 OA 主记录唯一存在，并将 `CollectionPackage` 与 OA 明细对齐。

**边界**：不重新下载源附件；不生成 PDF；不设置“待用户确认”“确认已完成归集”。

| 项 | 内容 |
|----|------|
| 输入 | `CollectionPackage`、OA 列表/明细、`OrganizationRules` |
| 输出 | `OaSyncResult`（`exists`、`robot_owned`、`status`、`added`、`updated`、`deleted`、`unresolved`、`next_action`） |
| 失败 | 登录/列表失败按系统异常重试；保存结果未知记 `待核验`，禁止重复保存 |

**步骤**：

1. **B1 主表创建/复用**：按报关单号（+合同编号）查重；存在则复用，不存在则新建。
2. **B2 归属判定**：`创建人=RPA` 为 `robot_owned`；历史/人工单据只读，不做附件维护。
3. **B3 读取 OA 快照**：读取全部明细区附件和状态；分页不完整时 `complete=False`。
4. **B4 计算差异**：按 `(kind, source_id)` 比较收集结果与 OA 快照。
5. **B5 执行同步**：新增上传、更新替换、删除仅限 RPA 行；每个动作后回查。
6. **B6 复核**：重新读取 OA 快照，统计 `unresolved`，写入结果表附件列。
7. **B7 状态读取**：输出 `next_action`，决定是否进入模块三。

主表创建/复用：

```text
for d in declarations:
    existing = oa.find_form(d)              # 按报关单号(+合同编号)筛选
    if existing:
        d.origin = robot_owned if existing.created_by == "RPA" else manual_or_history
        d.status = existing.status
        记录“报关单已存在”，不新建
        continue
    oa.open_new_form()
    oa.select_organization(d.company)
    oa.fill_new_form(d)                     # 出口日期/报关单号/合同编号
    oa.save_form()
    verification, found = oa.verify_form(d) # 列表回查创建人
    若 verification != COMPLETED: 记待核验，不重复保存
```

差异同步：

```text
if not d.robot_owned: skip
oa_snapshot = oa.read_attachments(d)
source = package.items

added   = source - oa   (按 (kind, source_id))
updated = 同 source_id 但 updated_at 变化
removed = oa.robot_managed - source   (仅在 package.complete=True 时判定)

for a in added:   oa.upload_attachment(d, a); oa.verify_attachment
for u in updated: oa.delete_attachment(d, old); oa.upload_attachment(d, new)
for r in removed: oa.delete_attachment(d, r); oa.verify_deletion
```

状态与下一步：

| OA 状态 | 机器人动作 | next_action |
|---------|------------|-------------|
| 附件归集中 | 不做 PDF，结果表记“等待用户确认” | `wait_user` |
| 待用户确认 | 同上 | `wait_user` |
| 确认已完成归集 | 进入模块三 | `merge_pdf` |
| 已归集为PDF 且 PDF 有效 | 跳过 | `done` |
| 已归集为PDF 但 PDF 缺失 | 历史单据补下载或重新生成 | `merge_pdf` |

条件必要附件（在 `rules.required` 基础上追加）：

| 条件 | 必要附件 |
|------|----------|
| 成交方式=CIF 且 保费非空 | CIF保险单 |
| 成交方式=EXW 且 运费非空 | 国内运费形式发票 |
| 监管方式含“进料” | 保税核注清单 |

| 项 | 内容 |
|----|------|
| 失败 | 单类附件失败记录后继续其他类型；上传结果不确定时禁止重试，先回查 |
| 幂等 | 以 `(kind, source_id)` 判断是否已存在；同名文件不重复上传 |

> 设计要点：一卡通按“更新时间 ≥ 基线”查询时，返回集不含未变更项，不能据此推断删除。删除同步依赖全量快照或源侧删除标记；若源系统无法提供，删除动作转人工，程序记录“删除待人工”。

### 8.6 模块三：合并PDF

**目标**：对已确认的单据，按组织配置顺序把 OA 现有附件合并为一个 PDF，回写 OA 状态与结果表。

**触发条件**：

1. `OaSyncResult.status == 确认已完成归集`；或
2. `status == 已归集为PDF` 且“归集的PDF路径”为空/文件不存在（历史单据补生成或补下载）。

**边界**：不新增/删除源附件；不修改用户状态；不回退状态。

| 项 | 内容 |
|----|------|
| 输入 | `OaSyncResult`、OA 附件快照、`OrganizationRules.pdf_order` |
| 输出 | `PdfResult`（`path`、`page_count`、`merged_at`、`uploaded`、`status_verified`） |
| 失败 | 必要附件缺失：`BusinessPending`，不改状态；合并/上传失败：保留原状态，下轮重试 |

**步骤**：

1. **C1 重新核验**：再次读取 OA 快照，确认状态仍为“确认已完成归集”、必要附件齐全、快照 `complete=True`。
2. **C2 下载附件**：逐行下载到 `06_临时文件/{run_id}/pdf/{单据}/`，校验大小>0、可解析。
3. **C3 排序**：按 `pdf_order` 排序；同类型多附件按 `附件更新时间` 升序；未列入顺序的必要附件追加末尾并告警。
4. **C4 合并**：按第 9 章规则合并，生成临时 PDF 并校验页数。
5. **C5 回写 OA**：上传 PDF（如启用）→ 状态改“已归集为PDF”→ 保存并回查。
6. **C6 时间对齐**：读取 OA 修改时间作为“归集PDF时间”。
7. **C7 更新结果表**：写 H/I 列与“打印”页签。

组织归集范围（PDD 4.3.3.2）：

| 组织 | 打印/归集范围 |
|------|----------------|
| 珠海 | 销售发票、合同、提单、报关单、放行通知单、电子委托协议 |
| 泰兴 | 报关单、销售发票、合同、提单、放行通知单、电子委托协议 |
| 荆门 | 报关单、销售发票、放行通知单、合同、提单、装箱单、电子委托协议、代理报关发票、国内运输发票、CIF保险单、国内运费形式发票；保税核注清单需归集但如不打印则不列入 `pdf_order` |

**失败处理**：

| 场景 | 处理 |
|------|------|
| 状态已变化 | 跳过，记录“状态已变化，未生成PDF” |
| 必要附件缺失 | 阻断，结果表记缺失类型，保留“确认已完成归集” |
| 附件格式不支持 | 该附件不合并，记 `待人工`，不静默跳过 |
| 上传结果不确定 | 回查状态后再决定，禁止重复上传 |
| PDF 已存在 | 原子替换，旧版本移入 `PDF/archive/{run_id}/` |

### 8.7 单张单据编排

```text
for d in declarations:
    if d.exists_in_oa and not d.robot_owned:
        pkg = None                          # 历史/人工单据不收集、不维护源附件
        sync = oa_sync.read_only(d)         # 只读状态与现有附件
    else:
        pkg = collect(d)                    # 模块一
        sync = oa_sync(d, pkg)              # 模块二
    if sync.next_action == "merge_pdf":
        pdf = merge_pdf(d, sync)            # 模块三
    result_workbook.save(d, sync, pdf)
```

说明：

1. 历史/人工单据即使状态为“附件归集中”，也不执行模块一、二，仅在“确认已完成归集”时执行模块三。
2. 模块一、二失败但主表已建：保留 `CollectionPackage`，下一轮复用。
3. 模块三失败：状态保持“确认已完成归集”，下一轮自动重试。

### 8.8 模块间数据契约

| 对象 | 关键字段 | 生产者 | 消费者 |
|------|----------|--------|--------|
| `CollectionPackage` | `declaration_key`、`items`、`missing`、`complete`、`fetched_at`、`manifest_path` | 模块一 | 模块二 |
| `OaSyncResult` | `exists`、`robot_owned`、`status`、`added`、`updated`、`deleted`、`unresolved`、`next_action` | 模块二 | 模块三、结果表 |
| `PdfResult` | `path`、`page_count`、`merged_at`、`uploaded`、`status_verified` | 模块三 | 结果表 |

契约约束：

1. `CollectionPackage` 只读传递，模块二不得修改源ID与更新时间。
2. `OaSyncResult.next_action` 仅取 `wait_user`、`merge_pdf`、`done`、`manual`。
3. `PdfResult.path` 必须为最终归档路径，不得指向临时文件。

### 8.9 单张单据状态流转

| 阶段 | 状态 | 进入下一阶段条件 |
|------|------|------------------|
| 待处理 | `待收集` | M01 解析成功 |
| 模块一 | `收集中` → `已收集`/`部分收集` | 需求清单处理完成 |
| 模块二 | `OA已创建` → `附件已同步`/`附件待补` | 主表存在且差异处理完成 |
| 等待用户 | `等待用户确认` | OA 状态变为“确认已完成归集” |
| 模块三 | `PDF生成中` → `已归集为PDF` | PDF 生成并回写成功 |
| 结束 | `成功`/`失败`/`待人工` | 结果表写入完成 |

### 8.10 失败边界与重跑

| 模块 | 失败场景 | 影响 | 重跑方式 |
|------|----------|------|----------|
| 模块一 | 共享盘/接口失败 | 该单据 `complete=False` | `--stage collect`，复用已有 manifest |
| 模块二 | OA 登录/保存失败 | 该单据未同步，PDF 不执行 | `--stage sync`，按源ID幂等 |
| 模块三 | 合并/上传失败 | 状态保持“确认已完成归集” | `--stage pdf`，重新核验后执行 |
| 结果表 | 文件被占用 | 本轮结果未落盘 | 自动重试；仍失败记日志并保留内存结果 |

### 8.11 结果表更新与轮次收尾（M09）

| 时机 | 写入内容 |
|------|----------|
| 模块二结束 | 附件存在标识/路径/时间、状态、运行状态、异常信息 |
| 模块三结束 | 归集的PDF路径/时间、打印页签 |
| 收尾 | 起止时间、汇总统计 |

收尾步骤：

1. 汇总各组织、各年份的单据数、PDF 数、失败数。
2. 更新 `run_state.json`（仅成功/部分成功）。
3. 发送企微结束消息与邮件（见第 13 章）。
4. 清理临时文件（保留 manifest 与审计）。
5. 释放单实例锁、关闭浏览器。

## 9. PDF 归集详细设计

### 9.1 输入与顺序

1. 打开 OA 单据，读取全部明细区附件。
2. 按 `OrganizationRules.pdf_order` 排序；同一类型多附件按 `附件更新时间` 升序。
3. `pdf_order` 未覆盖但属于 `required` 的附件，追加到末尾并在日志告警。
4. `pdf_order` 中不存在实际附件的类型：记录缺口；若属于必要附件则阻断，否则跳过。

### 9.2 文件获取

| 来源 | 获取方式 |
|------|----------|
| OA 明细行 | 修改态逐行点击下载图标，保存到 `06_临时文件/{run_id}/oa/{单据}/{类型}_{源ID}.pdf` |
| 历史已归集 PDF | 同源 URL 下载或共享盘路径读取，校验为有效 PDF |
| 非 PDF（图片） | 转为 A4 页面后合并；其他格式（xlsx/docx）不合并，记“格式不支持”，转人工 |

### 9.3 合并规则

```text
writer = PdfWriter()
for att in ordered_attachments:
    reader = PdfReader(att.path)
    校验：未加密、页数>0
    for page in reader.pages: writer.add_page(page)
    writer.add_outline_item(f"{序号}.{类型}", start_page)
输出到 06_临时文件/{run_id}/{报关单号}.pdf
校验：页数>0、大小>0、可重新打开
原子移动到 03_Output/{组织}/{YYYY}/PDF/{报关单号}.pdf
```

命名与覆盖：

| 项 | 规则 |
|----|------|
| 文件名 | `{报关单号}.pdf`（组织目录已隔离，无需合同号） |
| 覆盖 | 同名文件原子替换，旧版本移入 `PDF/archive/{run_id}/` 保留一次 |
| 加密 | 不加密 |
| 书签 | 每类附件一个书签，便于打印核对 |

### 9.4 上传 OA 与状态回写

| 步骤 | 说明 |
|------|------|
| 1 | 打开单据，核对报关单号+合同编号 |
| 2 | 进入“修改” |
| 3 | 上传 PDF 到“归集的PDF”字段/附件区（如启用上传） |
| 4 | 状态改为“已归集为PDF” |
| 5 | 保存并关闭，回查列表状态 |
| 6 | 读取 OA 修改时间作为“归集PDF时间” |

> 待确认冲突：PDD 4.3.3.7 要求“OA：上传归集的PDF”，而现有录制实现的 `upload_pdf` 注明“不上传合并PDF，只更新状态”。开发前需与用户确认；建议以 PDD 为准默认上传，并提供配置开关 `OA配置.上传归集PDF`（是/否），两种模式共用同一套校验与回查。

### 9.5 时间一致性

1. `归集PDF时间` 优先取 OA 保存后的“修改时间”。
2. OA 未返回修改时间时取本机时间，写入前后各取一次，取保存完成时刻。
3. 结果表 I 列与 OA 时间必须同源；允许误差 ≤2 秒，超差记异常并提示人工核对。
4. 重跑同一单据时，若 OA 已有时间和 PDF，覆盖前保留 archive 版本。

## 11. 异常处理与重试

### 11.1 错误分类

| 异常类 | 含义 | 处理 |
|--------|------|------|
| `ConfigError` | 配置缺失/格式错误/凭据不可用 | 终止本轮，企微告警，不发业务邮件 |
| `SystemFailure` | 网络、登录、页面加载、接口 5xx | 按重试次数重试；仍失败记单据失败，继续其他单据 |
| `BusinessPending` | 业务前置不满足（重复、缺字段、待人工、快照不完整） | 不重试；记“待人工/跳过”，继续 |
| `ImplementationRequired` | 页面结构变化、定位不唯一、未确认规则 | 不重试；截图+日志，终止当前单据 |

### 11.2 重试策略

| 场景 | 次数 | 间隔 | 备注 |
|------|------|------|------|
| 全局默认 | `基础配置.重试次数`（默认 3） | `重试间隔（秒）` | 指数退避不超过 30 秒 |
| 登录 | 3 | 5 秒 | 失败终止 |
| 保存/上传结果未知 | 0（先回查） | — | 禁止盲目重复保存/上传 |
| 文件被占用 | 5 | 2 秒 | 结果表保存 |
| 下载失败 | 3 | 2 秒 | 校验文件大小>0 |
| 通知发送 | 3 | 5 秒 | 失败不影响业务结果 |

### 11.3 降级与继续

1. 单张单据失败不影响其他单据。
2. 一卡通失败：该单据标记“一卡通附件待补”，继续 BIP 与 PDF 判定（PDF 会因必要附件缺失而阻断）。
3. BIP 失败：同上，记录“BIP 待补”。
4. OA 不可用：终止本轮，保留已完成的结果表写入。
5. 通知失败：业务结果照常落盘，日志记录，下一轮不补发历史结果（除非启用“通知补发策略”）。

4. 附件顺序与 OA 配置完全一致。
5. 异常单据有明确“运行状态+异常信息”，不影响其他单据。
6. 邮件/企微内容与 PDD 4.5 一致，跨年度附件齐全。

## 18. 未决事项与风险

| 编号 | 事项 | 影响 | 建议 |
|------|------|------|------|
| O01 | 归集 PDF 是否上传 OA | PDD 要求上传，现有录制实现为不上传 | 与用户确认；默认上传并提供开关 |
| O02 | 一卡通删除无法从时间过滤结果判定 | 删除同步可能漏项 | 要求一卡通提供全量快照或删除标记；否则删除转人工 |
| O03 | BIP 数据获取方式未定（报表/SQL） | 销售发票与运费发票无法自动化 | 尽快提供报表或只读账号 |
| O04 | 国内运输发票/国内运费形式发票两个明细区 | 现有代码阻断，无法自动上传 | OA 确认使用哪个明细区 |
| O05 | 历史单据已归集 PDF 的下载入口 | 历史 PDF 无法回读 | 提供 OA 附件入口或共享盘路径 |
| O06 | 打印按钮无 VBA | 按钮不可用 | 二期提供启用宏模板或外部监听 |
| O07 | 结果表第 2 行示例行 | 可能被误写或误统计 | 上线前确认删除/保留 |
| O08 | 模板表头错别字（T1、Z1） | 重命名会导致列错位 | 程序按别名兼容，模板暂不修改 |
| O09 | 组织全称与目录名不一致 | 归档路径错 | 配置中维护组织全称映射 |
| O10 | 缺失基础模块 | 代码无法导入运行 | 开发前补齐 `core.errors` 等 |
| O11 | 共享文件被占用 | 结果表保存失败 | 提示用户复制查看，程序重试 |
| O12 | 共享目录实际层级与六类文件命名规则未固化 | 待处理单据扫描、附件匹配失败 | 现场确认目录结构与文件名关键字；先按第 7.4 节约定实现并保留可配置匹配规则 |
